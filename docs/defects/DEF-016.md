# DEF-016: the configured Ollama model never reached the code that used it

**ID:** DEF-016
**Legacy:** none (recorded only in commit `0fc7e9c`)
**Kind:** defect
**Status:** fixed
**Severity:** blocking
**Class:** config-resolution
**ODC:** Assignment/Initialisation, Missing; trigger: Hardware/Software Configuration
**Component:** `app/config.py` :: `Settings`, `app/models.py`, `app/seed.py`
**Found:** guideline reparse and reindex failed on every chunk with a 404 from
`/api/generate`
**Added:** 2026-10-18
**Fixed in:** commit `0fc7e9c` (not in any `CHANGELOG_v*.md`)
**Test:** none
**Theme:** T5

---

## Symptom

Every chunk of a guideline reparse returned 404 from Ollama's `/api/generate`.
All 10 chunks failed identically, and `.env` plainly contained
`OLLAMA_MODEL=qwen3:32b`.

## Root cause

Three things had to line up, and none of them did. The web application never
called `load_dotenv()`. pydantic-settings reads `.env` only into fields declared
on `Settings`, and `ollama_model` was not declared. So the `os.getenv` calls in
`models.py` and `seed.py` returned `None`, the hardcoded fallback `qwen3.5:9b`
was written into every `ai_profiles` row, and `index_guideline` then sent that
stored `base_model` to the service, overriding the service's own default.

`qwen3.5:9b` and `qwen3.5:35b` are not real Ollama tags, so the fallback could
never have worked. They appeared in the service default, the admin template, both
example env files, the compose file and the documentation.

## Fix

Declare `ollama_model` on `Settings` and read it from there in `models.py` and
`seed.py`. Replace the placeholder tags everywhere they appear so a fresh
install cannot reproduce the failure, and expose the configured model to
templates as `default_llm_model` rather than hardcoding it in the admin form.

## Verified

Reparse and reindex complete against the configured model.

## Tests

None. A configuration-resolution defect of this kind needs a test that asserts
the value reaching the consumer is the value in `.env`, which does not exist.

## For the thesis

T5. Worth reporting because the symptom pointed at the model server and the
cause was three layers away in configuration loading, and because the fallback
value was itself invalid, which turned a recoverable misconfiguration into a
hard failure. A default that cannot work is worse than no default: it converts a
missing setting into a confusing 404 rather than a clear startup error, which is
the gap [LIM-001](LIM-001.md) later closed.
