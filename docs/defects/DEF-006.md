## Symptom

Results could break outright, or attach to the wrong requirement, when the model
returned a scalar where a list was expected or when deduplication left two
requirements sharing an identifier.

## Root cause

Identity and provenance were taken on trust from model output. `source_pages`
was assumed to be a list, and semantic IDs were assumed unique after
deduplication. Neither holds for generated output, and the second is the more
dangerous because a collision produces a confidently wrong report rather than a
crash.

## Fix

Support a scalar `source_pages`, merge source pages rather than overwrite them,
normalise severity, bound request limits, skip disabled and ignored rules, and
assign unique IDs after deduplication.

## Verified

Covered by the offline suite.

## For the thesis

T4. A misassociated result is worse than a missing one, because it is reported
with the same confidence as a correct one and the student has no way to detect
it. This is the strongest single argument in the register for deriving
identifiers server-side instead of accepting them from the model.
