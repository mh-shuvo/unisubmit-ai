## Symptom

Every new installation has a Super Admin `admin@unisubmit.local` with the
password `Admin@123`, both printed in the README. If every Super Admin is
later removed or demoted, the next restart creates the account again.

## Root cause

`startup()` in `app/main.py` called `seed(db)`, which inserted the demo
faculty, programs and supervisors when the database was empty, and the demo
Super Admin whenever no `SUPER_ADMIN` row existed. Account creation was a side
effect of starting the web server.

## Reproduction

```
uvicorn app.main:app      # fresh database, before the fix
# log in at /admin/login as admin@unisubmit.local / Admin@123
```

## Fix

The web startup creates tables and nothing else. Bootstrap became two
deliberate commands in `app/seed.py`:

```
python -m app.seed demo-data                        # sample structure, no accounts
python -m app.seed super-admin --email you@example.edu   # password prompted, 12+ chars
```

`UNISUBMIT_ADMIN_PASSWORD` allows a non-interactive run inside a container.
The README no longer lists credentials.

## Verified

Before: starting the app against an empty `admin_users` table created one
account. After: the table is still empty; the `super-admin` command rejects
`Admin@123` and creates an account with a chosen 24-character passphrase.

## Tests

`test_web_startup_does_not_create_an_admin_account` (red before: one account
created) and `AdminBootstrapTests` (demo data creates no account; a weak
password is refused; a strong one is stored and verifies).

## For the thesis

T8. Qualifier `Extraneous`: the fault was code that should not have run at
that point, not a missing check. Existing installations keep their accounts;
anyone still using `Admin@123` should change it, which the application has no
screen for yet.
