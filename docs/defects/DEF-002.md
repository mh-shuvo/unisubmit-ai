## Symptom

A 500 rather than a 502: the model returned syntactically valid JSON, so parsing
succeeded, and the crash happened later while consuming fields that were not the
expected type or were hung off the wrong root.

## Root cause

Parsing was treated as validation. Once `json.loads` succeeded nothing checked
that the root was the expected object, or that each result and suggestion had
fields of the expected shape, before the server indexed into them.

## Fix

Validate the semantic result and suggestion field shapes before consuming them.
Attempt at most one repair, and validate the repaired payload too. Output that
is still bad after the repair returns 502; a repair service that is unavailable
returns 503. No result is fabricated as PASS to get past a bad payload.

## Verified

Covered by the offline regression suite, including the case where the repair
itself returns something invalid.

## Tests

`ai_service/test_validation_fix.py :: ValidationFixTests.test_invalid_shape_repaired_once`
and `test_invalid_repair_returns_502`.

## For the thesis

T4, and it touches T3. The decision not to fabricate a PASS when the payload
cannot be understood is the same principle that [DEF-009](DEF-009.md) had to
establish separately in the deterministic engine: an unreadable answer must
never be reported as a compliant one.
