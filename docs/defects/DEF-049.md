## Symptom

A Super Admin opening `/admin/configuration` does not get a clean "forbidden"
response; the request fails inside the framework instead.

## Root cause

Every unit page refuses other roles with `raise HTTPException(403)`. This one
wrote `return HTTPException(403)`: the exception object became the page's
return value, which FastAPI then tried to send as the HTML response. No data
was shown, so the refusal held, but by accident.

## Fix

The page raises, through the same role check as every unit page
(`u.role != AdminRole.UNIT_ADMIN`).

## For the thesis

T8, and a borderline `insecure-default`: the access check did not behave as
written, and only the response type made it fail closed. One keyword is the
whole defect, which is the case for checking each protected route by test
rather than by reading.
