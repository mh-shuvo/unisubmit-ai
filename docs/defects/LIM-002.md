# LIM-002: existing `ai_profiles` rows still hold the stale model name

**Legacy:** none (recorded in the body of commit `0fc7e9c`)
**Kind:** limitation
**Status:** open
**Severity:** major

**ODC:** n/a (limitation)
**Component:** `ai_profiles.base_model` in `unisubmit.db`
**Found:** while fixing [DEF-016](DEF-016.md); the fix changes what is written
to new rows and does not touch rows already written
**Added:** 2026-10-18
**Fixed in:** not fixed
**Test:** none
**Theme:** T5

---

## Statement

[DEF-016](DEF-016.md) wrote the invalid tag `qwen3.5:9b` into every
`ai_profiles` row created while the configuration defect was live. The fix
declares `ollama_model` on `Settings` and corrects the default, so new rows are
right, but existing rows keep the stale value and `index_guideline` still sends
that stored `base_model` to the service.

## Consequence

Any installation that ran the affected versions still reproduces the original
404 for profiles created before the fix, even though the code is now correct.
A reader of the code would conclude the defect is fixed; for existing data it is
not.

## What closing it requires

A one-off update of `ai_profiles` rows holding the placeholder tags, or a
migration that resolves `base_model` through `Settings` when the stored value
is not a tag the server offers. The second is the better fix because it also
covers a model being removed from the server later.

## For the thesis

T5. A code fix and a data fix are different deliverables, and a defect that
wrote bad data is not closed when the writing stops. Worth stating in the
evaluation section if any reported result was produced on a database that
predates the fix.
