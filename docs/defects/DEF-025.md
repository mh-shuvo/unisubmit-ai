# DEF-025: async routes run synchronous database and file work on the event loop

**ID:** DEF-025
**Legacy:** none (restructuring plan, problem 4; task P0.2)
**Kind:** defect
**Status:** fixed
**Severity:** minor
**Class:** event-loop-blocking
**ODC:** Timing/Serialisation, Incorrect; trigger: Logic/Flow
**Component:** `app/main.py` :: `submit`, `resubmit`, `save_queue_version`, `add_version`, `review_guideline_rules`, `super_ai`
**Found:** architecture review of `app/main.py`; the routes were declared `async def` while every statement in them was synchronous
**Added:** 2026-11-14
**Fixed in:** commit `4848c62`
**Test:** `tests/test_queue_and_uploads.py` :: `WebProcessTests.test_async_routes_do_not_use_the_database_on_the_event_loop`
**Theme:** T7

## Symptom

Uploading a thesis or a guideline briefly stalls every other request: the
upload is copied to disk, inspected with PyMuPDF and written to the database
on the server's event loop. The stall lasts as long as the PDF inspection,
seconds for a long document.

## Root cause

FastAPI runs a plain `def` route in a threadpool and an `async def` route on
the event loop. Six routes were `async def` but awaited nothing that does real
I/O (`save_queue_version` was `async` with no `await` inside;
`review_guideline_rules` awaited only `request.form()`), so their SQLAlchemy
queries, `shutil.copyfileobj` and `inspect_pdf` calls ran on the loop.

## Reproduction

```python
import inspect
from fastapi.routing import APIRoute
from app import main
from app.db import get_db

[
    r.endpoint.__name__
    for r in main.app.routes
    if isinstance(r, APIRoute)
    and inspect.iscoroutinefunction(r.endpoint)
    and any(d.call is get_db for d in r.dependant.dependencies)
]
# before: ['super_ai', 'add_version', 'review_guideline_rules',
#          'index_guideline', 'submit', 'resubmit']
```

## Fix

The routes are plain `def`. `super_ai` calls a synchronous `health()` in
`app/ai_service_client.py`; `review_guideline_rules` receives its dynamic form
through an async dependency (`_form_data`) and does its database work in the
threadpool. `save_queue_version` is synchronous.

`index_guideline` stays `async`: it awaits the AI service for up to 25 minutes
inside the request, which is [DEF-038](DEF-038.md) and needs the queue, not a
threadpool.

## Verified

The reproduction above lists six routes before the fix and only
`index_guideline` after it.

## Tests

`test_async_routes_do_not_use_the_database_on_the_event_loop` asserts the list
is empty apart from `index_guideline`. Red on the pre-fix code (five
offenders), green with the fix.

## For the thesis

T7, the request-path twin of [DEF-024](DEF-024.md). The test is a structural

`async def` route that takes a database session, which is the cheapest point
