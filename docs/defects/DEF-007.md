# DEF-007: guideline parse client and server budgets were misaligned

**ID:** DEF-007
**Legacy:** none (recorded only in commit `98cb791`)
**Kind:** defect
**Status:** fixed
**Severity:** major
**Class:** timeout-misalignment
**ODC:** Timing/Serialisation, Incorrect; trigger: Workload/Stress
**Component:** `app/ai_service_client.py` :: `parse_guideline_profile`, `ai_service/main.py` :: `extract_guideline_profile`
**Found:** long sequential LLM chunk extraction on local hardware, where a
guideline long enough to need many chunks outran the client budget
**Added:** 2026-10-16
**Fixed in:** commit `98cb791` (not in any `CHANGELOG_v*.md`)
**Test:** none
**Theme:** T5

---

## Symptom

Parsing a guideline document failed partway through on local hardware, although
the AI service was still working on it.

## Root cause

The `httpx.AsyncClient` timeout in the web application and the
`asyncio.wait_for` timeout in the AI service were set independently. Guideline
extraction runs the model once per chunk, sequentially, so total time scales
with document length; on local hardware the client reached its limit while the
service was still inside its own.

## Fix

Align both budgets at 1500 seconds, the client `httpx.AsyncClient` timeout and
the service `asyncio.wait_for` timeout together. The commit also added
`docs/guideline_parse_and_index_pipeline.md`.

## Verified

By reparsing a guideline that previously failed. No numbers were recorded at the
time, which is a gap: see [LIM-005](LIM-005.md).

## Tests

None. The budget relationship holds between two constants in two files and is
not exercised by any test.

## For the thesis

T5. The second instance of the pattern in [DEF-005](DEF-005.md), on a different
call path, found three weeks later. Two occurrences are a coincidence; the third
in [DEF-015](DEF-015.md) makes it a design observation about per-call budgets in
a sequential LLM pipeline, where cost scales with input length rather than being
bounded by a constant.
