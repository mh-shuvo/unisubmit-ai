# DEF-014: the semantic layer returned NOT VERIFIED for every requirement

**ID:** DEF-014
**Legacy:** D7 (`docs/validation_defects_and_fixes.md`)
**Kind:** defect
**Status:** fixed
**Severity:** blocking
**Class:** llm-context-budget
**ODC:** Algorithm/Method, Incorrect; trigger: Workload/Stress
**Component:** `ai_service/main.py` :: `_extract_target_section`, `call_ollama`
**Found:** all 42 semantic requirements returned `NOT VERIFIED`, including
facts plainly present in the submitted document
**Added:** 2026-10-17
**Fixed in:** v9.11, commit `6e394f9`
**Test:** none; verified end to end
**Theme:** T4

---

## Symptom

Every one of the 42 semantic requirements came back `NOT VERIFIED`, including
requirements whose evidence was unmistakably in the document. The model was
never refusing; it was never receiving the task.

## Root cause

`_extract_target_section` returned the entire document when a rule named no
target section, once per rule. The resulting prompt was roughly 972,000
characters against a `num_ctx` of 16,384. Ollama truncates from the front and
says nothing, so the instructions and the JSON schema, which sit at the start of
the prompt, were discarded and the model received only a tail of document text
with no task attached.

A single prompt carrying every rule also overran the output budget, so even a
correctly framed call had nowhere to put its answers.

## Fix

Return `""` when there is no target section. Batch validation at
`SEMANTIC_BATCH_SIZE = 12` so prompt and output stay inside `num_ctx` 16,384 and
`num_predict` 4,096. Bound per-rule evidence at `SECTION_EVIDENCE_CHARS = 3000`
with a shared full-text fallback, trim the shared retrieval context, and slim
the output schema to the fields the server actually consumes. Keep one unusable
batch from discarding the batches that succeeded. Warn in `call_ollama` when a
prompt exceeds the context budget.

## Verified

Prompt requirements payload fell from about 914,000 characters to about 15,500.
Semantic passes went from 0 to 24 on a real UI submission, with 0 crashes and 0
timeouts across 88 rules.

## Tests

None. The defect is a property of prompt size against a model's context window,
which the offline suite does not exercise. The `call_ollama` size warning is the
standing detection mechanism instead, which is a weaker guarantee than a test
and is recorded as such.

## For the thesis

T4, and the single most instructive defect in the register. Three properties
made it hard: the truncation was silent, it removed the instructions rather than
the data because they come first, and the resulting behaviour, uniform
`NOT VERIFIED`, is indistinguishable from a model that simply cannot find the
evidence. The system's honest failure mode from [DEF-009](DEF-009.md) is what
disguised it. Worth stating plainly: safe failure semantics and diagnosability
pull against each other, and this is the case that shows it.
