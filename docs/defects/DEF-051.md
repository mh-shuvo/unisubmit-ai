# DEF-051: an SMTP failure after a passed validation re-runs the validation and can mark it failed

**ID:** DEF-051
**Legacy:** none (found while moving the supervisor email to its own job, task P3.6)
**Kind:** defect
**Status:** fixed
**Severity:** major
**Class:** job-coordination
**ODC:** Function, Incorrect; trigger: Logic/Flow
**Component:** `services/core/unisubmit/main.py` :: `process_job` (removed in v10.2)
**Found:** reading `process_job` to split it into handlers: the email is sent inside the validation job, after its results are committed
**Added:** 2026-11-15
**Fixed in:** v10.2, commit `74ca214` on branch `phase-1-tooling-layout-migrations`
**Test:** `services/core/tests/integration/test_queue_and_uploads.py` :: `ValidationHandlerTests.test_passed_validation_queues_the_supervisor_email`, `EmailHandlerTests.test_smtp_failure_is_retried_not_fatal`
**Theme:** T7

---

## Symptom

With SMTP configured but unreachable, a thesis that passes validation is
validated again, by the model, two more times, and then shown to the student
as "Validation Failed", although its report says PASSED.

## Root cause

`process_job` committed the validation results and then called
`send_submission_email`, which raises when the SMTP server refuses the
connection. The exception left `process_job`, so the worker treated the whole
validation as failed: it requeued the job, which ran the deterministic rules
and the minutes-long semantic validation again, and after the third attempt
set the version and submission to "Validation Failed". The job's unit of work
was "validate", but the email made "validate and notify" one unit with one
retry policy.

Without SMTP configured the email function returns `False` instead of
raising, which is why the demo never showed it.

## Reproduction

```
# set UNISUBMIT_SMTP_HOST to a host that refuses port 587, submit a PDF that
# passes; the queue page shows the job retried, then the submission fails
```

## Fix

The supervisor email is its own `send_email` job (task P3.6), queued by the
validation handler only when the result is PASSED and the version has no
`emailed_at`, and committed in the same transaction that completes the
validation job. Its SMTP errors are retried on their own schedule; a final
failure sets the email status to "Failed" and leaves the validation result
alone. The email handler skips a version that already has `emailed_at`.

## Verified

The two tests above; an end-to-end run of the real worker showed a passed
validation followed by a `send_email` job recording "SMTP Not Configured".

## For the thesis

T7. A job's retry policy belongs to one side effect. Bundling a cheap,
flaky side effect (SMTP) with an expensive one (the model) made the cheap
one's failures cost the expensive one's time, and its final failure rewrote
the expensive one's result.
