## Symptom

Anyone who can reach port 8001 can list the guideline collections, run
retrieval against them, send arbitrary prompts to the local model through the
validation and parsing routes, and call `DELETE /rag/collection/{name}` to
wipe a program's indexed guideline.

## Root cause

The AI service was designed as an internal component and had no
authentication at all; isolation was assumed rather than enforced, and
[DEF-030](DEF-030.md) published its port on every interface.

## Reproduction

```
curl -X DELETE http://<host>:8001/rag/collection/<collection>   # before: 200
```

## Fix

A shared token, `AI_SERVICE_TOKEN`, is required on every route except the
liveness probes `/` and `/health`. The service checks
`Authorization: Bearer <token>` with `hmac.compare_digest` in an app-wide
dependency, refuses to start (pre-flight) when the token is missing or shorter
than 32 characters, and answers 503 if it somehow runs without one. The web
app's settings require the same token, and `app/ai_service_client.py` sends it
on every call.

## Verified

Before: a request without a token reached `DELETE /rag/collection/tv_1` and
the Qdrant client's `delete_collection` was called. After: 401 and no call; a
wrong token is 401; the right token reaches the route. On the native service
started for the Mac demo, `GET /rag/collections` without a token returned 401.

## Tests

`TokenTests` (six cases) were red on the pre-fix service (503 or 200 instead
of 401). `test_every_ai_call_sends_the_service_token` was red (no header) and
is green. The existing `test_validation_fix.py` and `test_guideline_fix.py`
clients now send the token.

## For the thesis

T8. The service holds no student data at rest, but it does hold the one
resource the whole system is built around, the local model, and the indexed
guidelines every validation is grounded in. "Internal" is a deployment
property, and the deployment did not provide it.
