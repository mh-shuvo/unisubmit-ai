## Symptom

None observed yet. Any `docker compose pull` or fresh install fetches
whichever Qdrant release is newest that day, against a `qdrant_storage`
volume written by an older one and a client written for an older API.

## Root cause

`image: qdrant/qdrant:latest`. The AI service already carries compatibility
code for one Qdrant API change ([DEF-004](DEF-004.md), the `query_points` and
legacy search paths), so the drift is not hypothetical for this component.

## Reproduction

```
docker compose pull qdrant     # before the fix: whatever is newest today
```

## Fix

Pinned to `qdrant/qdrant:v1.19.2`, the version the running demo stack reports
(`GET :6333` → `"version":"1.19.2"`), so the existing volume is opened by the
release that wrote it. Upgrading becomes a deliberate change.

## Verified

`docker compose config` shows `qdrant/qdrant:v1.19.2`; the native AI service's
pre-flight against the demo Qdrant reported `server=1.19.2`.

## Tests

`test_images_are_pinned` rejects untagged and `latest` images. Red before
(`qdrant/qdrant:latest`), green after.
