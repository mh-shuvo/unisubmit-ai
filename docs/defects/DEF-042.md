## Symptom

Rows written by the Docker app hold paths such as
`/app/storage/submissions/submission_3_v1_….pdf`. A web app or worker running
natively against the same database, or the same stack after moving its
storage volume, cannot open any uploaded PDF or report: downloads return 404
and validations fail.

## Root cause

Every stored path is `str(STORAGE / …)`, an absolute path that includes the
location of the code in the environment that wrote it.

## Reproduction

```
# with the Docker stack's database, run natively:
DATABASE_URL=postgresql://…@127.0.0.1:5433/unisubmit uvicorn app.main:app
# open a submission and "View PDF": 404, the path is /app/storage/...
```

## What closing it requires

Paths relative to the storage root, resolved through one function with a
containment check, and a one-off script to rewrite existing rows (task P2.9).
The Mac demo runbook avoids the problem by keeping the web app and worker in
Docker and running only Ollama and the AI service natively.

## For the thesis

T8. A new class, `runtime-environment`: behaviour that depends on where the
code runs rather than on the code path. [LIM-008](LIM-008.md) is the hardware
side of the same class.
