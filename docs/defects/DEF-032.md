## Symptom

Two programs in one department named `M.Sc. (CSE)` and `M.Sc. CSE` share one
guideline index. Indexing the second program's guideline deletes the first
one's chunks (`recreate=true`), and from then on the first program's theses
are validated against the second program's guideline, with nothing in the
report to say so.

## Root cause

`make_collection_name` built the name from department, program, submission
type and version **names**, each passed through `slugify`, which maps every
run of non-alphanumeric characters to `_`. Program names are not unique (the
`programs` table has no constraint on `name`), and `slugify` merges names that
differ only in punctuation: both examples above become
`cse_m_sc_cse_thesis_1_0`. The same would apply to two universities with the
same department and program names, which the restructuring plan introduces.

## Reproduction

```python
from main import make_collection_name   # ai_service/
make_collection_name("CSE", "M.Sc. (CSE)", "Thesis", "1.0") == \
    make_collection_name("CSE", "M.Sc. CSE", "Thesis", "1.0")   # True
```

## Fix

Callers name the collection. The web app indexes into `tv_{template_version.id}`
and validates against `template_version.rag_collection`, the name indexing
actually returned, so collections indexed before this fix keep working
without a re-index. The AI service accepts an optional `collection` on index,
search, validate and format-profile requests, validated against
`^[A-Za-z0-9_]{1,128}$`, and falls back to the legacy name only when none is
given.

## Verified

Before: indexing with `collection=tv_7` and `collection=tv_8` for the two
colliding programs wrote both into `cse_m_sc_cse_thesis_1_0`. After:
`tv_7` and `tv_8`. A path-like name (`../other`) is rejected with 422 before
Qdrant is touched.

## Tests

`CollectionNameTests` (four cases; three red before, the fallback case
guards existing collections) and the two web-app routing tests (red before:
no `collection` sent).

## For the thesis

T5, filed under `lossy-normalisation` because the cause is `slugify`
destroying the distinction between two names before the code that needed it
(Qdrant) saw them. It is the identity version of [DEF-019](DEF-019.md): a
normalising step that was harmless for display and wrong for the consumer
downstream.
