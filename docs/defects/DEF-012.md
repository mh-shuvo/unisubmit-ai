## Symptom

Two mandatory rules failed every submission, for a word count that was never
measured on any of them.

## Root cause

The targets `Abstract (M.S. thesis)` and `Abstract (Ph.D. thesis)` are the
guideline parser's own labels, written to distinguish two variants of the same
requirement. No document contains a heading with that text, so the target
matched nothing.

A second, opposite symptom shares the cause: a target that matched no line
examined nothing and therefore reported a vacuous PASS, which is
[DEF-009](DEF-009.md) reached by a different route.

## Fix

Strip parenthetical qualifiers with `_strip_qualifier`, and resolve heading
targets through `_heading_candidates` so a target that still matches nothing is
reported rather than passed.

## Verified

Both rules now locate the abstract and measure its word count. Confirmed end to
end through the student UI.

## Tests

`tests/test_format_validation_rules.py :: TargetHandling.test_parenthetical_qualifier_is_stripped`,

class covering unmatchable and qualified targets.

## For the thesis

T1. The parser's own annotation leaked into the namespace the engine searches,
so a label meant for a human reader became a literal string to match. Two
components agreed on a field name and disagreed on what it denotes, which is a
boundary problem rather than a coding error, and it is the kind of defect that
testing each component in isolation will not surface.
