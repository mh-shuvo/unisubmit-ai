## Symptom

With the images from task P1.1, no service starts: `unisubmit migrate`,
`uvicorn` in the web app and `uvicorn` in the AI service all fail with
"not found", although the files exist in `/app/.venv/bin`.

## Root cause

The multi-stage Dockerfiles built the virtual environment in `/src/.venv` and
copied it to `/app/.venv` in the final stage. Console scripts are small
Python files whose first line names the interpreter by absolute path:
`#!/src/.venv/bin/python`. That path does not exist in the final image, and the
shell reports the script itself as "not found". The restructuring plan's
example Dockerfile has the same flaw.

Importing the package still worked (`python -c "import unisubmit.main"`), which
is all the P1.1 check exercised.

## Reproduction

```
docker compose -p rehearsal up -d --build
docker compose -p rehearsal logs migrate     # sh: 1: exec: unisubmit: not found
```

## Fix

`UV_PROJECT_ENVIRONMENT=/app/.venv` in the build stage, so the environment is
built at the path it runs from and copied unchanged.

## Verified

Same rehearsal: `migrate` adopted the v9.14 schema and exited 0, then the web
app and the worker started and served pages.

## For the thesis

T8, `runtime-environment`: correct code, wrong place. Found only because the
deployment was started, not just built. Checking that a package imports is
not the same as checking that its entry points run.
