## Symptom

Validation appeared to fail from the web application while the AI service was
still generating, and the error the student saw carried no detail about why.

## Root cause

Two faults in one client. The timeout was 240 seconds against an AI service
whose generation budget was 300 seconds and which could then make a second
repair call, so the caller could abandon work that was still in progress and
would have succeeded. Separately, the client discarded the HTTP status and the
JSON error detail from the service, so whatever the service did manage to say
about the failure never reached the application.

## Fix

Raise the validation timeout to 660 seconds, enough for generation plus one
repair, and preserve the HTTP status and JSON error detail in the exception
surfaced to the core application.

## Verified

Part of the v9.10.1 patch validation. Live generation was not exercised; the
offline suite does not cover wall-clock behaviour.

## Tests

None directly. The budget relationship is a configuration invariant rather than

parse path and again as part of [DEF-015](DEF-015.md).

## For the thesis

T5. The same mistake appears three times in this register on three different
call paths, which is the argument for treating client and server budgets as one
declared pair rather than two independent constants. That generalisation is
worth more in the paper than any of the three individual repairs.
