**ID:** DEF-040
**Legacy:** none (restructuring plan, problem 8; task P4.1)
**Kind:** defect
**Status:** fixed
**Severity:** minor
**Class:** insecure-default
**ODC:** Algorithm/Method, Incorrect; trigger: Logic/Flow
**Component:** `app/security.py` :: `hash_password`, `verify_password`
**Found:** architecture review
**Added:** 2026-11-14
**Fixed in:** v10.3, commit `057cede` on branch `phase-1-tooling-layout-migrations`
**Test:** `services/core/tests/integration/test_security.py` :: `PasswordTests.test_legacy_pbkdf2_password_still_logs_in`, `PasswordTests.test_legacy_hash_is_replaced_with_argon2id_at_login`
**Theme:** T8

## Symptom

None visible to users. If the `admin_users` or `student_users` table leaked,
passwords would be cheaper to brute-force than current guidance intends.

## Root cause

`hash_password` implements PBKDF2-HMAC-SHA256 by hand with 180,000
iterations and a custom `salt:digest` format. OWASP's current recommendation
for PBKDF2-HMAC-SHA256 is 600,000 iterations, and its preferred algorithm is
Argon2id. The format has no algorithm or cost marker, so the cost can never be
raised for existing hashes.

## Reproduction

```python
from app.security import hash_password

hash_password("x")  # 'salt_hex:digest_hex', fixed 180,000 iterations
```

## Fix

New hashes are Argon2id from `pwdlib` (task P4.1). A `LegacyPbkdf2Hasher`
recognises the old `salt_hex:digest_hex` format and verifies it, but never
writes it; `verify_and_update` returns an Argon2id hash after a successful
login with an old one, and the login stores it. An email that matches no
account is checked against a dummy hash, so a wrong email and a wrong
password take the same time.

## Verified

The two tests above: a password hashed with the exact pre-v10.3 code logs
in, and its row holds an `$argon2id$` hash afterwards.

the kind of finding a security examiner looks for first.
