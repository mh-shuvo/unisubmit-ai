# DEF-040: passwords are hashed with hand-written PBKDF2 at 180,000 iterations

**ID:** DEF-040
**Legacy:** none (restructuring plan, problem 8; task P4.1)
**Kind:** defect
**Status:** open
**Severity:** minor

**ODC:** Algorithm/Method, Incorrect; trigger: Logic/Flow
**Component:** `app/security.py` :: `hash_password`, `verify_password`
**Found:** architecture review
**Added:** 2026-11-14
**Fixed in:** not fixed
**Test:** none

---

## Symptom

None visible to users. If the `admin_users` or `student_users` table leaked,
passwords would be cheaper to brute-force than current guidance intends.

## Root cause

`hash_password` implements PBKDF2-HMAC-SHA256 by hand with 180,000
iterations and a custom `salt:digest` format. OWASP's current recommendation
for PBKDF2-HMAC-SHA256 is 600,000 iterations, and its preferred algorithm is
Argon2id. The format has no algorithm or cost marker, so the cost can never be
raised for existing hashes.

## Reproduction

```python
from app.security import hash_password
hash_password("x")   # 'salt_hex:digest_hex', fixed 180,000 iterations
```

## What closing it requires

`pwdlib[argon2]` (Argon2id) for new hashes, with the existing format verified
once at login and rehashed transparently (task P4.1).
