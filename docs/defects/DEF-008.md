# DEF-008: `float()` was applied to guideline-parser text values

**ID:** DEF-008
**Legacy:** D1 (`docs/validation_defects_and_fixes.md`)
**Kind:** defect
**Status:** fixed
**Severity:** blocking
**Class:** nl-to-rule-translation
**ODC:** Algorithm/Method, Missing; trigger: Normal Mode
**Component:** `app/format_validation.py` :: `validate_format_profile`
**Found:** both AI jobs in the database were `FAILED` with no report at all,
`error_message` `could not convert string to float: '>=12'` and
`could not convert string to float: 'double'`
**Added:** 2026-10-17
**Fixed in:** v9.11, commit `6e394f9`
**Test:** `tests/test_format_validation_rules.py` :: `ParseRuleValues`
**Theme:** T1

---

## Symptom

A submission produced no validation report whatsoever. `validation_json` was
`[]`, `report_path` was empty and the job status was `Validation Failed`.

## Root cause

Qwen writes rule values as human text, not as bare numbers: `>=12` for a font
size, `double` for line spacing. `float()` raised on both, the exception escaped
the per-rule loop, and a single unreadable value destroyed all 88 rule results
for the job.

Two faults compound here. The first is reading human text as a number. The
second is that one rule's failure was allowed to end the whole evaluation.

## Fix

Parse values as text through `_parse_num_op`, which handles operator symbols
(`>=12`, `≥ 25`), textual phrases (`at least 12`, `no more than 150`), spacing
nouns (`single space`, `double spacing`) and word numbers (`double`,
`one and a half`), returning the number and the operator separately.

## Verified

Both previously failing jobs produced a complete report. Confirmed end to end
through a real UI submission.

## Tests

`tests/test_format_validation_rules.py :: ParseRuleValues`, eight cases
including `test_operator_prefix_is_not_a_crash` and `test_word_spacing_value`.

## For the thesis

T1, and the clearest example in the register of the central difficulty: the
guideline is written for a human, a language model turns it into a rule, and
the rule engine then has to accept whatever vocabulary the model chose. The
value and its operator arrive fused in one string, which is why
[DEF-013](DEF-013.md) existed as a separate defect: parsing the number was not
the same as honouring the comparison.
