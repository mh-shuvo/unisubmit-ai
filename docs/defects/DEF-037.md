## Symptom

A double-click on "Submit" on `/submit` creates two submissions with the same
title, program and file, each with a queued validation job. The student sees
both on the dashboard, and the model validates the same document twice.

## Root cause

`submit` always inserts a new `Submission` before calling
`save_queue_version`. The DEF-026 lock is per submission, so it cannot see a
duplicate of a submission that does not exist yet, and there is no key to
recognise two requests as the same upload.

## Reproduction

```
# log in as a student, fill in /submit, and double-click Submit
# the dashboard lists two submissions with the same title
```

## Fix

Every stored version now records the SHA-256 of its file (migration `0004`,
task P3.8). `submit` stores and fingerprints the upload, then locks the
student's row, so a double-click's second request waits for the first. It
then looks for a submission by the same student, for the same guideline,
still queued or validating, with a version of the same SHA-256, and if one
exists redirects to it and deletes the second copy. The submission, its
version and its job are committed together, so the second request always
sees the first one complete or not at all.

## Verified

`test_double_submit_creates_one_submission`: red with the duplicate check
disabled (two new submissions), green with it.
