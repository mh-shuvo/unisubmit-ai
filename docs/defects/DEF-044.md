## Symptom

If the model returns a semantic rule with `source_pages` as a number, saving
the parsed guideline profile fails with `TypeError: 'int' object is not
iterable`. If it returns the pages as a string such as `"12"`, the rule is
silently cited as pages 1 and 2.

## Root cause

The rule-merging logic exists twice: `_dedupe_semantic_rules` in
`ai_service/main.py` and `_dedupe_semantic_requirements` in `app/main.py`.
[DEF-006](DEF-006.md) fixed scalar and malformed `source_pages` in the AI
service copy by routing them through `_source_pages()`. The web app's copy
still iterates the raw value: `for x in r.get('source_pages') or []`, which
fails on an `int` and splits a string into characters. The web app runs its
copy on every parsed profile it saves and on every validation
(`_normalize_profile_severities`).

## Reproduction

```python
from app.main import _dedupe_semantic_requirements as merge

merge({"semantic_requirements": [{"requirement": "r", "source_pages": 12}]})
# TypeError: 'int' object is not iterable
merge({"semantic_requirements": [{"requirement": "r", "source_pages": "12"}]})
# ... "source_pages": [1, 2]
```

## What closing it requires

One owner for the helper: the shared contracts package that both services
import (task P6.1), with the DEF-006 regression cases run against it. A
stopgap is to port `_source_pages()` into the web app's copy.

## For the thesis

T4, beside [DEF-006](DEF-006.md). The model-output contract was enforced at
one of the two places that consume the output, so the defect was fixed and
still present. Duplicated logic turns a closed defect into an open one in
the copy nobody re-tested.
