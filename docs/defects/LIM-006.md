## Statement

There is no continuous integration of any kind: no `.github/workflows`, no
pipeline configuration, no pre-commit hook. The 46 `unittest` cases in
`tests/test_format_validation_rules.py`, the 12 in
`ai_service/test_validation_fix.py` and the 7 in
`ai_service/test_guideline_fix.py` run only when someone remembers to run them,
with

```
.venv/bin/python -m unittest discover -s tests -v
```

and, from `ai_service`, `python -m unittest -v test_validation_fix`.

## Consequence

The regression guarantee in this register is conditional. Entries closed as
`fixed` cite a test that fails if the defect returns, which is true, but nothing
runs that test on a change. A reintroduced defect would be caught at the next
manual run, which may be after the measurement it invalidates has been quoted.

The tests are also split across three locations with two different invocations
and different working-directory requirements, which makes "run everything" an
undocumented procedure rather than one command.

## What closing it requires

A single entry point that runs all three suites, and a workflow that runs it on
push. Neither needs a model, a database or a network: all three suites are
offline by construction.

## Progress

Task P1.10 adds `.github/workflows/ci.yml`: format, lint, types, import
contracts, migrations and every suite (the database tests on a PostgreSQL
service) on each pull request and each push to `main`. The suites now need a
database, which the workflow provides. This entry closes on the first green
run on a pull request, which has not happened yet.

## For the thesis

T6. Worth one sentence in the threats to validity: the regression evidence is
real but unautomated, so the claim is that each fix was verified at the time,
not that it remains verified now.
