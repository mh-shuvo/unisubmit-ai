## Symptom

Validation returned 502 with no report. The AI service had started cleanly and
answered `/health`, so the failure looked like a model or retrieval outage
rather than a parsing one.

## Root cause

The semantic path called `json.loads` directly, while the guideline parsing path
already had a tolerant object parser for exactly this output. Qwen emits
thinking blocks, code fences and short preambles around its JSON. Any of those
made the strict parse fail, which pushed an otherwise usable response into the
repair path and then into a 502.

The defect is the inconsistency: two call sites consuming the same model's
output, only one of them written for what that model actually emits.

## Fix

Reuse and improve the tolerant parser on the semantic path, so both consumers
of model output accept the same output shapes.

## Verified

Part of the 12 offline regression tests that pass against the real FastAPI
endpoint through ASGI with the model and retrieval dependencies mocked.

## Tests

`ai_service/test_validation_fix.py :: ValidationFixTests.test_qwen_thinking_fence_and_preamble`
drives a wrapped response through the endpoint and asserts it is accepted.

## For the thesis

T4. An LLM's output format is a contract that is only ever partly specified, and
the cost of a strict reader is paid in false outages rather than wrong answers.

permissive once the JSON parses.
