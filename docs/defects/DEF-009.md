## Symptom

A rule the engine could not decide was reported to the student as PASS. The
report asserted compliance that had never been measured.

## Root cause

Skipping a rule and passing a rule were the same code path. When evaluation
could not proceed the loop moved on, and the wrapper emitted PASS for the rule
it had not examined.

## Fix

Report undecidable rules as `NOT VERIFIED` through `_not_verified`, and exclude
them from the compliance-rate denominator so an unmeasured rule neither claims
compliance nor distorts the score.

## Verified

Confirmed end to end by a real UI submission: rules that cannot be decided now
appear as explicit `NOT VERIFIED` rows rather than silently inflating the pass
count.

## Tests

`tests/test_format_validation_rules.py :: NoSilentPass`, three cases covering an
unparseable value, a missing parsed value and an untargeted heading rule.

## For the thesis

T3, and the most important entry in the register for the argument the system
rests on. A compliance checker that fails open is worse than no checker,
because the student acts on an assurance that was never earned. The same
principle had to be established independently in the semantic layer, see
[DEF-002](DEF-002.md), and the decision to keep `NOT VERIFIED` out of the
denominator is a measurement-reporting choice worth defending explicitly in the
text.
