# DEF-045: the web app and the worker both create the schema, and on an empty database the worker crashes

**ID:** DEF-045
**Legacy:** none (introduced and found on branch `phase-0-demo-critical-fixes`, before merge)
**Kind:** defect
**Status:** fixed
**Severity:** blocking
**Class:** job-coordination
**ODC:** Timing/Serialisation, Extraneous; trigger: Concurrency
**Component:** `app/worker.py` :: `main`
**Found:** booting the new `docker-compose.yml` against fresh volumes to verify Phase 0; the `worker` container exited with status 1 a second after start
**Added:** 2026-11-14
**Fixed in:** commit `4848c62`
**Test:** `tests/test_queue_and_uploads.py` :: `WorkerTests.test_worker_waits_for_the_schema_instead_of_creating_it`
**Theme:** T7

## Symptom

On the first `docker compose up` of a new installation, the worker container
exits immediately and stays down. The web app works, students can submit,
and every job waits in the queue for ever.

## Root cause

The first version of the [DEF-024](DEF-024.md) fix gave the worker its own
`Base.metadata.create_all()` at startup, next to the web app's. On an empty
PostgreSQL database the two processes issued `CREATE TABLE` concurrently, and
the loser failed:

```
psycopg2.errors.UniqueViolation: duplicate key value violates unique
constraint "pg_type_typname_nsp_index"
DETAIL:  Key (typname, typnamespace)=(faculties, 2200) already exists.
```

`create_all` checks for each table and then creates it, which is not atomic
across processes. The compose services had no restart policy, so the crash
was permanent.

## Reproduction

```
docker compose -p fresh up -d --build      # first version of the branch
docker compose -p fresh ps -a              # worker  Exited (1)
```

## Fix

Only the web app creates tables. The worker waits until the `ai_jobs` table
exists, logging that it is waiting, and then starts. The `app` and `worker`
services restart unless stopped, so a crash of either is no longer permanent.
Both are interim measures until migrations run as a separate step before
either process starts ([DEF-039](DEF-039.md), task P1.8).

## Verified

Fresh volumes, same compose project: before, `worker Exited (1)`; after, the
worker logged "Waiting for the web app to create the database schema", then
"Queue worker started" two seconds later. It then processed a queued 73-page
thesis to `COMPLETED` in one attempt, and stopped cleanly on SIGTERM.

## Tests

`test_worker_waits_for_the_schema_instead_of_creating_it` starts the worker
against an empty database and asserts it created no tables. Red before the
fix (every table created), green with it.

## For the thesis

T7. A regression introduced by a fix for the same theme, and found only
because the verification booted the deployment from empty volumes rather than
against the existing database, where every table already existed and the race
could not happen. Qualifier `Extraneous`: the defect was a step the worker
should never have taken.
