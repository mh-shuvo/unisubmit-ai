## Symptom

Any failure inside retrieval surfaced as an undifferentiated 500 with nothing
logged, so a missing collection, an authentication failure and a genuine bug
were indistinguishable from the outside.

## Root cause

A broad exception handler mapped everything to 500 and swallowed the traceback.
This is why the v9.10.1 diagnosis had to proceed by reading source rather than
by reading logs, and it is the direct reason this register exists.

## Fix

Log startup versions, and log traceback detail for retrieval, generation, repair
and unexpected failures. Return 503 for an unavailable dependency rather than
500. Logs deliberately exclude student text and raw model output.

## Verified

Covered by the offline suite.
