# DEF-023: a dual-level guideline is blocked for every program

**ID:** DEF-023
**Legacy:** none
**Kind:** defect
**Status:** fixed
**Severity:** blocking
**Class:** nl-to-rule-translation
**ODC:** Checking, Missing; trigger: Normal Mode
**Component:** `ai_service/main.py` :: `_program_guideline_consistency`
**Found:** an admin uploaded a template written for both B.Sc. and M.Sc.
programs; parse-and-index returned "Program-guideline mismatch" and blocked
activation for the configured M.Sc. program
**Added:** 2026-11-13
**Fixed in:** commit `4f49fc3`
**Test:** `ai_service/test_program_consistency.py` :: `ProgramGuidelineConsistencyTests`
**Theme:** T1

---

## Symptom

Uploading a guideline template that explicitly states it applies to both
Bachelor of Science and Master of Science programs ends parse-and-index with:

> Program-guideline mismatch: Configured program appears to be a master-level
> program, while the guideline text contains a bachelor-level degree
> statement. Activation is blocked until the correct guideline is uploaded.

The same template is blocked for a bachelor program too, by the mirror
message. There is no configured program for which a dual-level guideline can
be activated, so the gate behaves as an unsatisfiable precondition for a
legitimate input shape.

## Root cause

The v9.3 consistency gate in `_program_guideline_consistency` collects degree
markers from the whole guideline text (`Bachelor of Science`, `Master of
Science`, `B.Sc.`, `M.Sc.` variants), then flags a mismatch whenever a
marker of the *opposite* level to the configured program is present — without
ever asking whether a marker of the program's *own* level is also present.
A dual-level guideline by definition contains an opposite-level marker for
any program, so the presence check that was meant to catch a wrongly uploaded
file instead rejected a correctly uploaded one. The missing condition was
"and no marker of the configured level exists".

## Reproduction

```python
# inside the ai-service container: docker compose exec ai-service python
from main import _program_guideline_consistency

pages = [
    {
        "text": "This template applies to Bachelor of Science (B.Sc.) "
        "and Master of Science (M.Sc.) theses."
    }
]
_program_guideline_consistency("M.Sc. in CSE", pages)
# before the fix: {'mismatch': True, ...}  → activation_blocked
```

Any guideline PDF whose extracted text contains both level statements
reproduces it through the admin UI for any B.Sc. or M.Sc. program.

## Fix

Two changes in the same commit. First, the mismatch condition: the
gate now maps the detected markers and the configured program each to a
degree level and flags a mismatch only when the guideline's degree
statements *exclude* the program's level — a guideline naming several
levels passes for any of them. Second, the vocabulary: alongside the four
original science-degree patterns, the text side now recognises loose
`Bachelor's`/`Masters` wording and a doctoral level (`Doctor of
Philosophy`, `Ph.D.`/`PhD`, `doctoral`), and the program side classifies
doctoral program names, `MSc`/`BSc` without dots included. The
`detected_degree_markers` diagnostics gained the new labels but kept the
original four.

## Verified

Before the fix: `mismatch=True` for an M.Sc. program against the dual-level
text above (and `True` for a B.Sc. program against the same text). After the
fix: `mismatch=False` for both, while the two genuine-mismatch cases
(bachelor-only text with a master program and the reverse) still return
`mismatch=True`, and a matching-level guideline still passes. Confirmed on
the rebuilt `ai-service` container.

## Tests

`ai_service/test_program_consistency.py :: ProgramGuidelineConsistencyTests`,
ten cases: the two dual-level cases that reproduce the defect, the two
genuine mismatches that must keep blocking, a matching-level pass, and five
for the vocabulary extension (loose "Masters programme" wording clearing an
M.Sc. program, a PhD program against doctoral-only and bachelor-only texts,
a bachelor program against a doctoral-only text, and a guideline with no
degree statement at all). The original five were seen red against the
pre-fix `main.py` (the two dual-level cases fail, the three guards pass)
and green against the fixed one, both run inside the service container; all
ten are green on the extended code.

## For the thesis

T1, beside [DEF-020](DEF-020.md) and [DEF-022](DEF-022.md): a concept the
guideline states plainly ("applies to B.Sc. and M.Sc.") that the checker's
logic could not represent — its model of a guideline admitted exactly one
degree level. Unlike the fail-open entries, this one fails *closed*: the
safety gate itself rejected valid input, which is the inverse cost of the
same vocabulary problem and arguably the more visible one, since it blocks an
administrator rather than mis-scoring a student.

The vocabulary boundary found during diagnosis — only four science-degree
patterns, so plain "Masters"/"Bachelor's" wording and the entire doctoral
level were invisible, leaving the gate inert for PhD programs and still
fail-closed for informally worded dual-level templates — was removed in the
same pass rather than registered as a limitation. What remains out of
vocabulary: non-science degree abbreviations (B.A., M.A., B.Eng., M.Eng.,
MBA) are caught only when the text also uses the words "bachelor", "master"
or "doctor"; an abbreviation-only guideline still produces no markers,
which fails open (no block), not closed.
