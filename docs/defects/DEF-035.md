# DEF-035: a stale per-profile AI service URL overrides the configured one

**ID:** DEF-035
**Legacy:** none (found while planning task P0.10)
**Kind:** defect
**Status:** fixed
**Severity:** blocking
**Class:** config-resolution
**ODC:** Assignment/Initialisation, Incorrect; trigger: Logic/Flow
**Component:** `app/main.py` :: `process_job`, `index_guideline`; `app/seed.py` :: `seed`
**Found:** planning the move of the AI service out of Docker for the Mac demo; the demo database holds two AI profiles whose `service_url` values are `http://127.0.0.1:8001` and `http://ai-service:8001`
**Added:** 2026-11-14
**Fixed in:** commit `4848c62`

## Symptom

In the Docker stack, every validation for the seeded B.Sc. CSE project report
profile fails three times and ends "Validation Failed": the worker calls
`http://127.0.0.1:8001`, which inside the app container is the app container
itself. Moving the AI service, for example out of Docker for the Mac demo,
breaks every other program the same way, while the AI status page, which uses
the configured URL, reports the service as healthy.

## Root cause

Each `ai_profiles` row stores a `service_url`, written once when the row is
created: the seed wrote `http://127.0.0.1:8001`, and `index_guideline` wrote
whatever `AI_SERVICE_URL` was at the time. `process_job` and the guideline
parse call used that stored value, while indexing and the health check used
`settings.ai_service_url`. A setting changed in configuration therefore never
reached the validation path, and one route (`index_guideline`) used two
different URLs for its two calls.

## Reproduction

```
docker exec unisubmit_ai-db-1 psql -U unisubmit -d unisubmit -At \
  -c "select id, service_url from ai_profiles"
# 1|http://127.0.0.1:8001     <- unreachable from inside the app container
# 2|http://ai-service:8001
```

## Fix

There is one AI service per installation. `process_job` and the parse call
in `index_guideline` use `settings.ai_service_url`; the per-profile field is
no longer read for routing (it is still shown on the AI management page, and
new demo rows record the configured URL).

## Verified

With a profile pointing at `http://stale-host:8001`, the worker's validation
call and the guideline parse call now go to the configured URL; before, both
went to the stale host.

## Tests

The two tests named above, red before (the stale URL was used) and green
with the fix.

## For the thesis

T5, a third instance of the pattern behind [DEF-016](DEF-016.md) and
[LIM-002](LIM-002.md): configuration copied into a database row at creation
time silently outranks the configuration file afterwards. Severity is
`blocking` because affected programs get no validation result at all.
