# DEF-036: the queue worker swallows its own failures

**ID:** DEF-036
**Legacy:** none (found while doing task P0.1)
**Kind:** defect
**Status:** fixed
**Severity:** major
**Class:** observability-gap
**ODC:** Checking, Missing; trigger: Logic/Flow
**Component:** `app/main.py` :: `queue_worker` (now `app/worker.py` :: `run_job`, `run_forever`)
**Found:** moving the worker into its own process; the loop's outer handler was `except Exception: db.close(); sleep(3)` with no logging
**Added:** 2026-11-14
**Fixed in:** commit `4848c62`
**Test:** `tests/test_queue_and_uploads.py` :: `WorkerTests.test_failure_after_a_database_error_is_recorded_and_logged`
**Theme:** T6

## Symptom

A job whose processing fails on a database error stays `PROCESSING` with no
error message, and nothing appears in any log. The queue looks busy, the
student waits, and an operator has nothing to go on.

## Root cause

Two missing steps in `queue_worker`. When `process_job` raised, the handler
set the job's status and committed without rolling back first; after a failed
flush the session refuses every statement until it is rolled back, so that
commit raised `PendingRollbackError`. That second exception reached the outer
`except Exception`, which closed the session and slept, without logging
either error. The job keeps the `PROCESSING` status committed when it was
claimed.

## Reproduction

The regression test makes `process_job` violate the `ai_jobs` unique
constraint and then runs the worker once. With only the rollback removed
again, the run raises:

```
sqlalchemy.exc.PendingRollbackError: This Session's transaction has been
rolled back due to a previous exception during flush.
```

## Fix

`run_job` rolls back before recording the failure, logs it with the job id
and attempt number (`logger.exception`), and then sets `RETRYING` or `FAILED`.
The loop's outer handler logs every iteration failure before sleeping.

## Verified

The job is `RETRYING` after one attempt, its error message names the unique
constraint, and an `ERROR` record is written to `unisubmit.worker`. With the
rollback reverted, the test errors with `PendingRollbackError`.

## Tests

`test_failure_after_a_database_error_is_recorded_and_logged`, seen red with
only the rollback removed and green with it.

## For the thesis

catches everything and logs nothing turns every unknown failure into "the
