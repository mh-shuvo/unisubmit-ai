## Symptom

Adding a column to a model works on a fresh database and fails on every
existing one: the first query that selects the column raises
`column … does not exist`, and the page returns 500.

## Root cause

The schema is created by `Base.metadata.create_all` at startup.
`create_all` creates missing tables but never alters existing ones, and the
project has no migration tool, so nothing carries a model change to a
database that already has the table.

## Reproduction

```
# add a column to SubmissionVersion, restart against the existing Postgres
# database, open a submission page: ProgrammingError, column does not exist
```

## What closing it requires

Alembic with a baseline revision taken from the current models, stamped onto
existing databases, and migrations run as a separate step before the web app
and worker start (task P1.8). Until then, constraints that would harden
[DEF-026](DEF-026.md) and [DEF-037](DEF-037.md) cannot be added safely.

## For the thesis

T8. A new class, `schema-drift`: the code and the database disagree about
the schema and nothing reconciles them. It blocked part of Phase 0, which is
how it surfaced.
